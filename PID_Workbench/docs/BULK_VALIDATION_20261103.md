# 2026-11-03 批量传输与滑动窗口实板验证

本轮已更新主机发送器、从机接收器和上位机。主机后续修正了无线实际发出时的计时及 USB 错帧隔离；从机接收器协议保持兼容。以下是两块 ESP32-S3 的真实传输结果，包含从机实际计算整份 SHA256。

**范围：电脑 USB → ESP-NOW → 从机 RAM/PSRAM。STM32 没有擦除或重烧，原应用保留。总烧录时间仍包含目标 Flash 擦除、写入和完整读回，不能用本表代替。**

参数：192 字节无线有效数据、8 包窗口、3072 字节 USB 批次、6144 字节主机缓存、加密开启、信道 1。

## 同一固件、同一文件的对照

| 64 KiB 文件 | 用时 | 有效速度 |
|---|---:|---:|
| 逐包等待 | 5.453 秒 | 11.74 KiB/s |
| 批量＋滑动窗口 | 2.313 秒 | 27.67 KiB/s |

本次同条件对照提速约 **2.36 倍**。这是单次实测，不是任何距离或干扰环境下的保证。更新前最初的旧固件基线为 64 KiB / 6.547 秒 / 9.78 KiB/s；后续排除了 USB 集线器异常，因此优先使用上面的同固件模式对照。

## 故障与兼容性

- 损坏 COBS 帧内嵌 `!step 99`：未执行指令，STEP 保持 0.01，接收进度为 0。
- 帧 CRC 正常但镜像内容与清单 SHA 不同：实际从机返回 `sha256_mismatch`。
- 中途留下不完整 USB 帧并关闭连接：新连接恢复文本控制，从 3072 字节的连续前缀续传，最终 SHA 通过。
- 人为丢弃全部无线数据：重传达到上限后明确超时，未进入目标烧录，暂存锁正常释放。
- 新固件强制 `--legacy` 路径通过；原有逐包功能保留。
- 原生模拟覆盖到 1 MiB、独立丢失数据/确认、乱序、重复、CRC 损坏、窗口边界、超时及计时器回绕；15 组原生测试通过，114 项 Python 测试通过。
- HTTP API 的 H2 内部回环：1024 字节全量一致，同一个发送键重试后累计发送仍是 1024 字节，零缺口、零 UART 错误；外部电平转换器保持关闭，目标板隔离。
- P/I/D/STEP、保存状态和 stream 与升级前一致，RUN 请求保持 STOP；无线已同步。
