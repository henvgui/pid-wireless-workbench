# 下载成功后串口失效：2026-11-03 修复记录

从机固件版本 **20261103.3**。本轮仅更新从机，不要求修改主机、上位机、Keil 配置或目标应用。

## 现象与定位

F407 SWD 下载显示校验和启动成功，之后 H2 发指令无反应、上位机收不到日志，整机断电才恢复。已在实板复现：旧任务 `d8cbd8c5be6e62385ff8c236` 返回完整读回通过、`start_ack=true`；重新打开 H2 后连续 6 秒收到 **0 B**。从机串口为 active、未暂停，UART 错误和丢弃均为 0。

旧 `ArmSwd::start()` 只脉冲 NRST、解除暂停，再检查 CPU 没有 HALT/LOCKUP，没有确认一次真正的系统复位，也没有检查 PC、SP 和中断屏蔽状态。这个启动判断不够严格：RAM 烧录器结束时 PC 位于 `0x20000012`，PRIMASK=1；若复位未完成，解除暂停可能继续执行 SRAM 尾部等待循环，无法证明用户应用及其串口中断恢复。

本轮确认了“旧启动确认存在缺口，更新启动流程后故障消失”。尚未单独测量 NRST 的实际波形，因此不将问题归因于某根接线或某个硬件元件。仅从历史 `start_ack=true` 不能证明目标应用已正常运行。

## 修复

烧录、完整 Flash 读回仍保持原流程。RUN 阶段改为：

1. 读出已验证应用的初始 SP 和复位入口，确认目标仍暂停。
2. 在暂停状态清除调试中断屏蔽，设置 reset catch。
3. 通过 AIRCR 发出一次 `SYSRESETREQ`，清除旧复位标记后等待新的 `S_RESET_ST` 和复位暂停；最多等待 1 秒，失败不重发擦写。
4. 核对 PC 与 Flash 复位入口一致、SP 与向量表一致、PRIMASK/BASEPRI/FAULTMASK/CONTROL 恢复，以及 Thumb 状态正确。
5. 清除 reset catch，恢复执行，再检查没有暂停、锁死或再次复位；通过后才返回启动确认。

另修正了 UART ROM 路径的交接顺序：局部 `HardwareSerial` 对象必须先析构，再通知另一核“下载完成”。Arduino 的析构函数会再次关闭全局 UART1，旧顺序存在恢复串口后又被析构关闭的竞争。此项代码已修正，但本轮实板用的是 F407 SWD，未重新验收 UART ROM 芯片。

从机 USB 新增 `!starttrace`，读取缓存的最近启动检查，不复位或暂停目标。例如：

```json
{"type":"starttrace","step":6,"reset_seen":true,"before_pc":"0x20000012","before_special":"0x00000001","pc":"0x08000230","sp":"0x20000c18","special":"0x00000000","dhcsr":"0x01010001"}
```

`step=6` 表示完成本次启动检查；`pc` 与 `sp` 是复位暂停时的值，不是运行中实时位置。`before_special` 含 RAM 算法遗留的 PRIMASK，复位后 `special=0`。未请求 RUN 时不会产生新的启动检查。

## 实板结果

目标为 STM32F407VET6，镜像 **10,252 B**，SHA256：

```text
ff0ab81d851a2d6e30faaa516c01cf2f7555bbaa80af0cc64599dc91c0380956
```

连续 3 次重烧相同镜像，在同一个 H2 115200/8N1 会话中验证，期间没有再手动复位或断总电源：

| 次数 | API 任务耗时 | 下载后约 3 秒收到 | 完整读回 / 启动检查 |
|---|---:|---:|---|
| 1 | 4.053 s | 7,646 B | 通过 |
| 2 | 4.061 s | 8,190 B | 通过 |
| 3 | 4.051 s | 8,565 B | 通过 |

同一会话的暂停次数依次增加，串口恢复后接收持续，错误和丢弃均为 0。随后以目标已有的 `S` 指令实测下行：发送共 2 B，目标回传速度从约 24/24 降至 **0/0**；停止后仍继续收到日志。电机按用户确认保持悬空，测试结束为停止状态。

软件检查：17 组 C++ 原生测试、117 项 Python 测试通过，从机 PlatformIO 编译通过。新增启动测试覆盖复位未发生、残留 SRAM PC、错误 SP、PRIMASK 未清、ROM 启动、Thumb 状态错误、丢失回应不重放及禁止误报启动成功。

结构化证据见 [uart_resume_validation_20261103.json](assets/uart_resume_validation_20261103.json)。原始记录在本机 `pid/work/uart_resume_20261103`，修改前源码和固件在 `pid/backups/before_uart_resume_20261103`；配对密钥及目标固件仅本地备份。

日常使用保持原操作：先连接 H2，Keil 下载期间接收暂停，下载并启动后自动恢复。`--no-run` 则按要求保持目标暂停，此时没有应用串口输出是预期行为。应用必须自行初始化串口并处理发送的指令；这些检查不代替目标应用的功能确认。
