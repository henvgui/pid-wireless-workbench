# 从机选择与颜色身份

2026-11-04，适用于完整主机 `host_flash` 与从机 `slave_flash_psram`（从机版本 `20261104.1`）。

## 主机操作

- **双击 P 按键**切到下一台已登记的从机，两次点击间隔不超过约 350 ms。
- **P 单击不执行操作**；长按 P 不切换从机。转动 P 继续调节 P 数值。
- OLED 顶部显示当前名称和序号，例如 `GREEN 1/1`。平时同时显示无线状态；切换后短暂显示所选名称。
- 当前只有 GREEN 一台，再次双击仍为 GREEN，保持当前无线会话。
- I、D 和 STEP 的短按切色保持原行为；STEP 长按 2 秒开关整圈 RGB。

主机保存已登记名单及当前选择，重新上电后恢复。该保存与 PID 参数的 SAVE 分开，不会覆盖未保存的 PID 数值。所有从机共享主机当前的 P/I/D/STEP；切换不会自动加载每台从机独立的 PID 配方。

颜色名称为固定的八种：`GREEN`、`BLUE`、`RED`、`YELLOW`、`CYAN`、`PURPLE`、`ORANGE`、`PINK`。按这个顺序循环已登记项，最多八台。

## 灯光和连接

- 主机 LINK LED：收到当前所选从机的有效应用层消息后常亮，失联后熄灭。
- 从机状态 RGB：连接并收到有效快照后，以自己的身份色常亮；未连接或未被选中时，以该色快速呼吸，周期约 600 ms。
- 手动 `!rgb` 可以覆盖状态灯，`!auto` 恢复自动指示。

切换会更换实际的加密 ESP-NOW 对端 MAC，并建立新的协议会话，清除旧对端的排队消息。只有所选从机与主机同步；其他从机逐渐超时离线。灯光表示 ESP32 链路状态，不能代替 STM32 执行确认。

## 登记第二台从机

当前已登记 GREEN，MAC 为 `44:1B:F6:8D:10:18`；主机 MAC 为 `44:1B:F6:8D:10:20`。

新从机须使用与主机相同的本地配对密钥。编译和上传时先按新板的真实 USB 身份调整上传工具配置，不能把旧板固定的 COM18 或序列号直接当作新板。密钥文件在 `PID_Shared/PIDLink/private/pair_keys.h`，不上传仓库。

1. 连接新从机 USB，在它的 USB 串口发送以下命令（换行结束）：

   ```text
   !identity BLUE
   !info
   ```

   `!identity` 保存身份色；从 `!info` 返回的 `mac` 读取新板实际 MAC。

2. 连接主机 USB，在主机串口登记该 MAC，例如下面的地址须替换为新板真实值：

   ```text
   !peer add BLUE AA:BB:CC:DD:EE:02
   !peer list
   ```

3. 关闭串口监视器后，双击主机 P 切换。OLED 应显示 `BLUE 2/2`，相应从机变为蓝色常亮。

这里使用显式登记；没有自动发现，也不会远程改写新从机的身份色。请保持从机 `!identity` 与主机登记的颜色名一致。同一个 MAC 不能登记成多个颜色。

主机 USB 管理命令：

| 指令 | 行为 |
|---|---|
| `!peer list` / `!peer` | 查看当前选择、名单、索引、双击及切换计数 |
| `!peer next` | 选择下一台，受与双击相同的占用检查约束 |
| `!peer select GREEN` | 选择指定的已登记从机 |
| `!peer add BLUE AA:BB:CC:DD:EE:02` | 新增或更新颜色对应的 MAC |
| `!peer remove BLUE` | 删除登记项；不能删除最后一项 |
| `!peer reset` | 恢复默认 GREEN 名单，不清除 PID 保存记录 |

名单来自主机 NVS。记录损坏时显示 `PEER CONFIG ERROR`，不会使用损坏的地址启动通信；可在确认目标后用 `!peer reset` 恢复。

## 切换限制

烧录暂存、传输、写入、校验，以及其他有待完成事务时拒绝切换。当前在线从机的 H2 双向串口或 H1 日志会话打开时，也需先在工作台关闭串口。主机处于 RUN 请求状态时先 STOP，等待当前在线从机确认后再切换。

被拒绝时 USB 返回 `peer_busy`，OLED 短暂显示提示，不改变当前选择。离线对端遗留的串口标记不会永久阻止换到另一台；真正执行中的烧录事务仍须先完成或中止。

烧录工具预检读取所选 `peer_mac`，在 Begin 时携带该 MAC，主机再次核对。预检后切换到不同 MAC 会使旧请求报 `conflict`；Begin 成功后则锁定选择，直至任务结束或中止。不要在旧任务状态未明确时换目标重试。

新会话默认不向目标 UART 自动发送电机控制帧；只有显式电机协议操作才启用当前会话的转发。普通串口和烧录继续按各自入口操作。

## 上位机与 AI

上位机顶部显示当前从机名称。`!get` / `!link` 新增 `peer_name`、`peer_mac`、`peer_index`、`peer_count`；现有 `/v1/device` 响应中可读取设备状态字段。烧录日志保存所选名称和 MAC，用于区分目标。

这一版没有增加 HTTP 名单管理或选择接口。需要登记时，先关闭工作台中占用主机的会话，再使用主机 USB 命令；不要同时用两个程序打开同一 USB 串口。现有 Keil、CLI 和 HTTP 烧录入口保持不变。

## 已验证范围

原生测试 19 组、Python 测试 129 项，两个 ESP32 固件及桌面程序构建通过。实板已验证 GREEN 连接、单台选择不重连、串口及固件事务期间拒绝切换、MAC 不匹配拒绝 Begin；临时登记不存在的 BLUE 地址后验证实际离线路由、GREEN 呼吸及切回重连，最后已删去测试项。

验证仅暂存并中止 64 B 测试镜像，未擦写或复位 STM32。多台真实从机同时供电的现场验收仍待后续硬件。记录见 [验证数据](assets/peer_selection_validation_20261104.json)。

现场已确认：P 单击不再切色，双击后 OLED 显示 `GREEN 1/1`，符合预期。本轮改动与记录保留在本地，尚未推送 GitHub。
