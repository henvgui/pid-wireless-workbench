# 主机与从机 ESP-NOW 第一版

2026-11-04 完整版 `host_flash` / `slave_flash_psram` 已支持颜色身份和已登记从机选择：**双击 P 切换，P 单击无动作**，OLED 显示名称及序号。单台 GREEN 不会因再次选择而重连。操作、登记、占用限制及测试范围见 [从机选择指南](../PID_Workbench/docs/PEER_SELECTION.md)。下文绿色固定状态灯与默认环境说明为早期版本记录；新版状态灯使用从机保存的身份色。

2026-10-17。当前默认：主机 `host_wireless`，从机 `slave_wireless`。

本版完成两块 ESP32-S3 之间的参数和启停请求通信。主机继续负责四旋钮、OLED、原有 RGB 灯效、本地 SAVE 和 USB；从机接收完整参数快照并回传确认。两端启用 Wi-Fi 射频用于 ESP-NOW，不连接路由器。

## 使用

- 主机 USB：COM14，设备身份 `44:1B:F6:8D:10:20`。
- 从机 USB：COM18，设备身份 `44:1B:F6:8D:10:18`。
- 两端均可用各自的 VS Code「编译 / 烧录」任务。端口已分别固定，避免同时连接时自动选错板。
- 两块板只需供电即可无线通信。两根 USB 同时接电脑便于观察和调试。
- 主机转 P/I/D 或 STEP 后，从机自动接收最新 P/I/D/STEP。USB 的 `!pid`、`!step`、`!move` 使用同一条同步路径。
- SAVE 保存到主机 NVS；从机当前只在 RAM 中镜像参数，不写目标板或从机 Flash。
- RUN/STOP 发出请求，主机收到从机确认后显示 ACK。本版没有启用目标板接口，电机等执行器不会因此动作。

## 显示和灯光

主机保留此前已确认的 RGB 渐变流水呼吸、旋钮彩虹拖影、互补色背景和 5 秒返回动画，亮度上限 30/255。

2026-10-17 连接指示调整：主机独立 LINK LED（LED2，GPIO38，低电平点亮）在收到有效从机应用层确认后常亮，未连接或失联时熄灭。调节参数期间保持常亮，不因单个快照等待确认而闪烁；失联检测约 1.5 秒。`!link` 的 `link_led_on` 表示程序当前发出的点灯状态，不代替现场观察灯珠。

OLED 顶部：

| 显示 | 含义 |
|---|---|
| `W OFFLINE` | 尚未连上或已失联 |
| `W SYNC` | 已收到从机消息，当前完整状态等待确认 |
| `W LINK` | 参数已同步，尚未发出启停请求 |
| `W RUN ACK` / `W STOP ACK` | 从机已确认对应启停请求 |
| `W ERROR` | 无线初始化失败，USB `!link` 查看 `radio_error` |
| `*` / `SAVED` | 当前参数未保存 / 与主机保存记录一致 |

从机在自动灯光模式下：未连接时绿色呼吸，连接并收到主机有效参数快照后绿色常亮。RUN/STOP 均保持绿色常亮，状态灯现在只表示连接状态；无线关闭或初始化失败也显示未连接呼吸。`!status` 的 `rgb_mode` 分别为 `link_breath` / `link_solid`。`!rgb` 可以暂时覆盖状态灯，`!auto` 恢复连接状态显示。关闭无线的历史诊断环境仍为绿色呼吸心跳。

这里的 ACK 只表示从机已接收、校验并更新 RAM 镜像，不是目标板执行确认。JSON 明确带 `ack_scope:"slave"`，目标板接口保持禁用。

## USB 指令

主机保留 [本地版指令](README_HOST_LOCAL.md)，另增加 `!link`。命令以 `!` 开头、换行结束，115200。

```text
!pid 1.25 0.10 2.50
!step 0.10
!link
!run
!get
!stop
```

`!get` 的新字段：`wireless`、`link_online`、`synced`、`ack_scope`。`synced` 只在从机已确认当前完整快照时为 true；刚修改参数或请求时为 false。`ack` 对应当前启停请求，尚未发出请求时为 false。

主机 `!link` 返回初始化状态、在线状态、同步状态、两端启动会话、最近消息间隔，以及发送、接收、重发、超时和丢弃计数。`encrypted:true` 表示已配置加密单播；`target_connected:false` 表示这一版未连接目标板协议。

从机：

| 指令 | 用途 |
|---|---|
| `!link` | 查询无线状态及 RAM 中的 P/I/D/STEP、revision、request_id、run_request |
| `!info` / `!status` | 芯片及运行诊断；`translator_oe` 应为 1 |
| `!ping`、普通字符 `1` | 应答及回显测试 |
| `!rgb R G B` / `!auto` | 手动颜色 / 恢复状态灯 |
| `!radio off` / `!radio on` | 关闭 / 重启无线，用于断链测试，USB 保持工作 |

主机无线版拒绝用 `!ackrun` 人工伪造无线确认，返回 `wireless_ack_required`。关闭无线的 `host_local` 环境保留原 USB 确认测试方式。

## 重发、失联和重启

采用固定信道 1、已知对端 MAC 和加密单播。完整快照为 48 字节，含版本、序号、两端启动会话、参数、请求状态及 CRC16。

旋钮连续变化以约 40ms 的最小发送间隔合并成最新状态；确认未到时每 80ms 重发，单轮最多 4 次，随后按心跳节奏继续恢复。平时约每 500ms 同步一次，用于保持状态和发现失联。MAC 层发送成功不会被当成参数已确认，必须收到匹配当前会话、序号和内容的应用层 ACK。

约 1.5 秒没有有效通信或有效确认时，主机会撤销 RUN 请求并转为 STOP；离线时拒绝新的 RUN。从机无线会话变化也会撤销 RUN，重新连接不会自动续跑，需要重新按 RUN。

从机失联时 `!link` 的参数仍可能保留最后一次收到的值；必须结合 `online` 判断新鲜度。状态灯同时恢复绿色呼吸。对目标板的电平转换器一直关闭，NRST/BOOT/SWD 未驱动；以后接目标板时还需实现目标端超时处理。

## 工程及恢复

共享协议与无线驱动在 `../PID_Shared/PIDLink/`，两个工程的 `lib_extra_dirs` 指向同一目录。

更换模组后需更新共享 `PIDLink.cpp` 中的 `hostMac` / `slaveMac` 并重新烧录两端；库会核对本机 MAC，不匹配时报告初始化错误。

`PIDLink/prepare_keys.py` 首次生成本机密钥文件 `private/pair_keys.h`，重复运行保留现有文件。两端编译共用该文件；换电脑时需带上此文件，或生成新密钥后给两端都重新烧录。文件已加入该库的 `.gitignore`，日志不输出密钥。

保留关闭无线的环境：主机 `host_local`、从机 `slave_diagnostic`。主机任务「主机：烧录本地版（关闭无线）」和从机任务「从机：烧录诊断版（关闭无线）」可切回。本地使用方式和独立外设测试仍保留。

## 后续功能

日常无线版还未接入目标 STM32/GD32 的 UART 参数协议、真实反馈曲线数据或目标板执行确认。当前从机的 GPIO47 始终为高，U4/U5 关闭；尚未进行目标固件烧写。

2026-10-17 后续新增独立选择的 `host_flash` / `slave_flash`：G431 ROM UART 烧录代码及完整文件无线传输已编写，实际目标擦写待接线联调。日常默认 `host_wireless` / `slave_wireless` 的目标接口仍关闭。新增烧录版的编译、接线、电脑工具、重传与校验说明见 [PIDFlash/README.md](../PID_Shared/PIDFlash/README.md)。
