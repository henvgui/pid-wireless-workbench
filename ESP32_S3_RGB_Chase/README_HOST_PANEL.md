# 主机：渐变流水呼吸、旋钮拖影与四参数显示

本文对应保留的灯效验收环境 `host_panel`。当前默认为 [主从无线版](README_WIRELESS.md)，继承本文的 RGB 与旋钮行为。关闭无线的本地功能版见 [本地与 USB 使用说明](README_HOST_LOCAL.md)。本文的 RAM 保存和文本自动回报仅指 `host_panel`。

## 操作

- 上电后：整圈显示渐变颜色，相邻 RGB 只差一小步，颜色沿灯环连续流动；所有灯共享同一条呼吸亮度曲线，一起变亮、变暗。呼吸周期约 4 秒，渐变色绕环流动一轮约 4 秒，暗部约为峰值的 10%。
- 旋转任意旋钮：取当前渐变在亮点位置的颜色，约 0.45 秒渐变进入一个共享拖影亮点，按旋转方向移动，保留最多 6 颗拖尾。其余灯低亮显示互补色（色相相差 180°），例如红配青、蓝配黄。
- 短暂停转：亮点和拖尾的位置保持，颜色继续按时间缓慢彩虹渐变，约 8 秒一轮；互补色背景同步变色。距离最后一次有效旋转或按下满 5 秒后，约 0.9 秒渐变回整圈流水呼吸，从停住的位置及超时当刻的颜色开始展开。
- 再次操作：从当前画面接续进入拖影，包括返回动画进行到一半时；四个旋钮共用这一处位置、颜色和拖尾。亮点在相邻 LED 之间插值移动，连续转动和反向时保持位置、速度连续，停转后约 0.1 秒收拢到目标灯位；参数立即更新。
- 按下一次旋钮：以该旋钮的下一个预设色重新开始彩虹渐变，切色约 0.25 秒，背景随之变成新的互补色，同时重新计时 5 秒；长按不重复触发。从空闲按下时采用 0.45 秒进入过渡。
- OLED 同时显示 P、I、D、STEP，高亮最近操作的数据。

| 数据 | 上电值 | 旋转作用 |
|---|---:|---|
| P | 0.00 | 按 STEP 增减 P |
| I | 0.00 | 按 STEP 增减 I |
| D | 0.00 | 按 STEP 增减 D |
| STEP | 1.00 | 选择 0.01、0.10、1.00、10.00 四档步长，到边界停止 |

P/I/D 范围暂定 0.00～9999.99。数据保存在 RAM，复位后恢复上电值。这是本地主机交互原型，尚未连接从机或目标控制板。

空闲转动旋钮时，拖影继承正在显示的渐变颜色。四个旋钮分别保存按键色板序号，初始为 P 绿、I 蓝、D 紫、STEP 红，按下时切到各自的下一个预设色。主机 RGB 亮度上限为 30/255，比上一版的 40/255 降低 25%，不启用 Wi-Fi 或蓝牙。

## VS Code 与 USB

- 任务「灯效验收版：编译」「灯效验收版：烧录」编译、上传 `host_panel`。命令行也可使用 `platformio run -e host_panel`。
- `Ctrl+Shift+B` 及「主机：编译 / 烧录」现对应 `host_wireless`，功能版协议见上方链接。各版本 USB 波特率均为 115200。
- 旧「旋钮：烧录」「OLED：烧录」「RGB：烧录」任务保留，分别用于独立外设测试和旧灯效程序。

USB 为 115200，普通字符回显。发送 `!status`（换行结束）或 `?`，返回 `HOST_PANEL` 状态和四个 `KNOB` 数据行，其中 `value` 为当前数值。查询状态不会延长拖影模式。

实物旋钮操作自动发送简短的 `INPUT name=P value=1.00 position=40` 行，每 50ms 合并更新一次；发送不等待电脑读取，缓冲满时保留最新待发值。完整诊断状态请主动发送 `!status`。自动回报不再包含完整 `HOST_PANEL`/`KNOB` 多行，以减少转动时串口发送对灯光刷新的影响。

常用命令：

| 命令 | 功能 |
|---|---|
| `!knob P` / `I` / `D` / `STEP` | 选择 USB 后续操作的数据 |
| `!move cw` / `!move ccw` | 模拟一次旋转，修改数值并唤醒拖影；计入 simulated，不算实物测试 |
| `!color next` / `!color 1`～`!color 8` | 切换所选旋钮的颜色并唤醒拖影 |
| `!brightness 0`～`!brightness 30` | 调整全局 RGB 亮度；上限 30，超限命令被拒绝 |
| `!reverse on/off` / `!edges 2/4` | 配置所选旋钮方向和跳变数，主机默认正常方向、2 跳变 |
| `!reset` | 恢复四个数值、初始颜色和位置，回到呼吸模式；保留亮度及旋钮方向/跳变设置 |
| `!rgbtest on/off` | 手动全灯红绿蓝诊断 / 返回主机交互显示 |

此环境始终使用一个共享亮点，`!display independent` 会返回错误。Windows 旧上位机的手动输入框可发送上述命令；原灯效按钮主要对应 `rgb_chase`。

使用者反馈旋转两个机械卡点才更新一次数值，主机默认计数改为 2 次信号跳变一步；适用于卡点交替落在 AB=00/11 的编码器，实际每格计数需现场确认。若某个旋钮出现一格变化两次，可先用 `!knob P`（或 I/D/STEP）选中它，再发 `!edges 4`。USB 修改只在本次运行有效，重新上电恢复固件默认设置；旧独立测试环境保留 4 跳变默认值。

当前状态包含 `rgb_style=gradient_breath`、`flow=gradient/manual`，分别表示整圈渐变流水呼吸和旋钮跟手拖影；`rgb_transition=1/0` 表示过渡进行中/已完成，`rgb_background=complement` 表示互补色背景，`rgb_accent_hue_deg` 是拖影实时目标色相（空闲时保留返回起始色），`rgb_manual_cycle_ms=8000` 表示手动模式彩虹周期；`brightness_limit=30` 表示主机亮度上限。各 `KNOB` 行的 `color/palette` 表示该旋钮保存的按键色板序号。渐变动画不改变四个数值，也不延长 5 秒超时。

`rgb_motion=subpixel_spring` 表示连续位置平滑，`rgb_position_milli` 为灯链上从 0 起算的视觉位置乘 1000（可含灯间位置），`rgb_frame_ms=4` 为目标刷新间隔，`rgb_dither=1` 表示低亮度颜色分帧补偿，`input_reports=compact` 表示非阻塞简短自动回报。`KNOB position` 仍是从 1 起算的整数目标位置。

## 引脚与验证

沿用已验证接线：RGB GPIO47；OLED SDA GPIO8、SCL GPIO9、地址 0x3C，使用可正常显示的 SSD1306 128×64 配置。四旋钮接线见 [四旋钮说明](README_KNOBS.md)。

OLED 使用独立任务及互斥保护的数据快照，RGB/旋钮在主循环处理中。Wire 统一配置 OLED 引脚，U8g2 不重复指定 SDA/SCL；RGB 沿用已确认可用的 RMT 时序。

2026-10-15 验证：

- 本机测试通过：上电呼吸、共享单亮点、停转保持、5 秒超时及再次唤醒、计时回绕、独立数值/颜色、步长与数值上下限。
- `host_panel` 编译、上传成功，旧 `knob_encoder_rmt` 环境也通过编译。
- 20 项真实 USB 检查通过，含参数变化、单亮点限制、OLED/RGB 同时正常、5 秒自动返回及再次触发；USB 模拟旋转与实物验证分别记录。
- 使用者现场回复「全部正常」，确认四旋钮、OLED 更新、按下切色、单个拖影及 5 秒后恢复呼吸均正常。

记录位于 `validation/host_ui_native_20261015.txt`、`host_panel_upload_20261015.txt`、`host_panel_usb_20261015.json` 和 `host_panel_physical_20261015.json`。

### 呼吸效果第二版

根据现场反馈，取消整圈彩虹位置缓慢移动的显示，改为整圈同步变色；最低灯效强度由 8/255 提高为 112/255，取消平方曲线造成的长时间暗部。最高强度及全局亮度上限 40/255 保持原设置。该调整只影响空闲呼吸，旋钮拖影、5 秒返回及四个数据的操作逻辑沿用此前版本。

本次编译、上传和原有本机逻辑测试通过，USB 确认 RGB 与 OLED 正常应答；记录见 `validation/host_panel_breath_v2_20261015.json`。使用者反馈第二版最暗时仍太亮，因此继续调整如下。

### 呼吸效果第三版

最低灯效强度由 112/255 降为 64/255，约为峰值的 25%；保留第二版的整圈同步渐变、4 秒呼吸及 12 秒变色周期。使用者反馈可以再暗一点。

### 呼吸效果第四版

### 呼吸效果第五版

### 整圈渐变流水，同步呼吸

按使用者澄清的效果实现：相邻灯的色相相差约 9°，首尾也平滑衔接；同一时刻整圈采用相同的亮度强度，随呼吸在 26/255～255/255 间变化。颜色按时间在灯环上连续移动，形成渐变流水；全局亮度上限仍为 40/255。旋钮操作时使用原有单个跟手拖影，5 秒无操作后回到渐变流水呼吸。

本机测试已覆盖相邻颜色/首尾衔接、整圈亮度同步、10% 暗部、颜色流动、旋钮拖影冻结、5 秒超时、时间回绕及数值/步长边界。编译、上传及 23 项 USB 检查通过，OLED 与 RGB 正常应答；记录见 `validation/host_ui_gradient_native_20261015.txt`、`host_panel_gradient_upload_20261015.txt`、`host_panel_gradient_usb_20261015.json` 及 `host_panel_gradient_acceptance_20261015.json`。使用者认可渐变效果，并要求流水速度加倍，因此流动周期从 8 秒调整为 4 秒，呼吸周期及暗部设置保持原值。

同时修正了 USB 状态回复的尾行延迟：部分 192 字节的末行会等到下一次查询才读到；回复末尾增加空行结束标记，按段排空发送后，整套 USB 检查通过。接收端忽略空行即可。

### 连续过渡与互补色背景

进入拖影时保留当时整圈画面，并继承原亮点位置的实时颜色，450ms 平滑进入手动显示；未处于亮点/拖尾的灯使用低亮互补色。旋转跟随平滑时间为 80ms，按下切色为 250ms，数值响应不延迟。停满 5 秒后，用 900ms 从停住的画面恢复渐变呼吸，渐变的起始色相和位置对齐停住的亮点。返回途中再转动，会捕获当时混合画面重新进入拖影。

本机测试通过颜色继承、互补色背景、进入/切色/返回边界的逐像素连续性、返回中断、定时回绕及原参数逻辑；主机编译、上传和 30 项 USB 检查通过，OLED/RGB 状态正常。使用者反馈「还行」，随后要求最高亮度降低约 25%，旋钮颜色随时间彩虹渐变。记录见 `validation/host_ui_transition_native_20261015.txt`、`host_panel_transition_upload_20261015.txt`、`host_panel_transition_usb_20261015.json` 及 `host_panel_transition_20261015.json`。

### 降低亮度，手动拖影自动彩虹渐变

主机全局亮度上限从 40/255 降为 30/255，降低 25%；呼吸暗部仍为峰值约 10%，4 秒呼吸/流水、两跳变编码和所有过渡时长沿用上一版。手动模式的亮点和拖尾共用连续变化的彩虹色相，8 秒一轮，停转时仅保持位置；背景始终取其互补色。继续转动不会重启颜色时钟，按下切色则从所选预设色重新渐变。5 秒超时按最后一次真实操作计时，返回呼吸时从超时当刻的拖影颜色接续。

本机测试通过持续彩虹、颜色时钟跨旋转保持、循环衔接、互补背景、过渡/返回中断及参数逻辑；编译上传和 35 项 USB 检查通过，含亮度上限接受/超限拒绝、停转时色相和帧数继续变化、5 秒返回、OLED/RGB 正常。使用者反馈扭动旋钮时仍不够平滑，继续调整如下。记录见 `validation/host_ui_rainbow_native_20261015.txt`、`host_panel_rainbow_upload_20261015.txt`、`host_panel_rainbow_usb_20261015.json` 及 `host_panel_rainbow_20261015.json`。

### 连续位置跟随与非阻塞自动回报

旋转不再重启整圈淡入，模式/切色过渡与 5 秒操作计时分别运行。视觉亮点使用临界阻尼位置平滑，在每个新目标到来时保留当前位置及速度，光强在相邻灯之间插值；反向时拖尾用 120ms 平滑换向。拖影逐渐融入互补色背景，避免尾端低亮像素突然跳成另一种颜色。刷新间隔从 20ms 缩短为 10ms，参数仍按有效卡点立即更新。

自动实物输入回报改成非阻塞 `INPUT` 行；完整 `!status` 保留分段排空和末尾空行，以保证诊断查询完整。亮度上限 30、8 秒手动彩虹、4 秒呼吸/流水、10% 暗部、5 秒返回及两跳变计数保持原设置。

本机测试通过快速连续卡点与反向时的位置/速度连续性、进入和切色过渡不被转动重启，以及原有彩虹、背景、超时和参数逻辑。编译、上传及 39 项 USB 检查通过，含手动模式刷新速率与停止后的视觉目标收拢，OLED/RGB 状态正常；实物转动观感待确认。记录见 `validation/host_ui_smooth_native_20261015.txt`、`host_panel_smooth_upload_20261015.txt`、`host_panel_smooth_usb_20261015.json` 及 `host_panel_smooth_20261015.json`。

### 当前：低亮度颜色渐变分帧补偿

使用者澄清不平滑指 RGB 颜色渐变。原驱动将每通道的 0～255 直接缩放取整到 0～30，只有 31 个瞬时输出档位，慢速渐变会在同一档停留后跳到下一档。本版保留缩放余数，在后续高速帧中补偿，使平均输出继续保留细小色差；灯珠和颜色通道的补偿相位均匀错开，避免整圈同步进退一个档位。

主机刷新间隔设为 4ms；每帧各通道仍不超过亮度上限 30，黑色保持为零，满通道保持为 30。发送给灯珠的每通道数据仍为 8 位，细化来自时间上的平均输出。该补偿仅在 `host_panel` 启用，其他独立测试固件沿用原输出。彩虹速度、呼吸周期、背景、操作计数和模式过渡沿用上一版。

补偿本机测试通过：0～40 亮度范围内的恒定通道平均值精确、黑色/满通道不闪变、输出不超限、变化渐变的累计误差受控及整圈补偿相位错开。编译、上传和 40 项 USB 检查通过，OLED/RGB 状态正常。使用者现场确认「颜色渐变顺滑了」，保留本版固件。记录见 `validation/rgb_dither_native_20261015.txt`、`host_panel_color_dither_upload_20261015.txt`、`host_panel_color_dither_usb_20261015.json` 及 `host_panel_color_dither_20261015.json`。
