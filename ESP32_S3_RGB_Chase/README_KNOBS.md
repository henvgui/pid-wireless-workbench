# P / I / D / STEP 四旋钮 RGB 控制

## 使用

默认每个旋钮有自己的亮点、颜色和拖尾：

| 旋钮 | 初始颜色 | A / B / 按键 GPIO |
|---|---|---|
| P | 绿 | 4 / 5 / 6 |
| I | 蓝 | 7 / 10 / 11 |
| D | 紫 | 12 / 13 / 14 |
| STEP | 红 | 15 / 16 / 17 |

GPIO 按原主机 PCB 网络核对。RGB 使用 GPIO47，共 40 颗。

- 顺时针 / 逆时针旋转：只移动自己的亮点，保留最近经过的位置作为最多 6 颗拖尾。
- 停止旋转：亮点和拖尾的位置、颜色保持不变。
- 按下一次：只切换自己的颜色；长按不连续触发。
- 颜色顺序：红、橙、黄、绿、青、蓝、紫、粉，再回到红。
- 亮点/拖尾重合时按各 RGB 通道的较高值叠加，可能显示混合颜色。

需要四个旋钮共同控制一个亮点时，发送 `!display shared`；恢复独立亮点发送 `!display independent`。两种模式各自保留显示状态，切换时不会清掉另一种模式的位置和颜色。

目前这是旋钮和灯光的硬件测试，没有接入 PID 数值、无线调参或目标板控制。

## 编译和烧录

在 VS Code 打开本目录的 ESP32_S3_RGB_Chase.code-workspace。

- 四旋钮独立测试环境为 `knob_encoder_rmt`，通过任务「旋钮：编译」编译。当前默认环境及 Ctrl+Shift+B 已改为主机整合固件 `host_panel`，详见 [主机说明](README_HOST_PANEL.md)。2026-10-15 起沿用已确认点亮全部 40 颗灯的全白测试时序：0 码高/低电平 300/950ns，1 码高/低电平 900/350ns，每位 1250ns。旧的 Adafruit 版本仍可用 `--environment knob_encoder` 编译。
- 运行任务 **旋钮：烧录** 上传；**旋钮：串口监视** 查看输入状态和计数。
- 原 **STEP：烧录** / `step_encoder` 保留为旧 STEP 单旋钮程序。
- 原 **RGB：烧录** / `rgb_chase` 保留为 20 种自动灯效程序。
- 上传前释放其他程序占用的串口。

USB 使用 115200，普通字符回显（发 `1` 收到 `1`）。控制命令以 `!` 开始，以 LF 或 CRLF 结束。原上位机的底部输入框可发送这些命令；原灯效按钮适用于 `rgb_chase` 固件。

## USB 命令

| 命令 | 功能 |
|---|---|
| `!status` 或 `?` | 总状态及四个旋钮的引脚、原始 A/B/按键电平、位置、颜色和计数 |
| `!help` | 帮助 |
| `!knob P` / `!knob I` / `!knob D` / `!knob STEP` | 选择后续 USB 命令控制的旋钮，不改变其余旋钮；名称大小写均可 |
| `!display independent` / `!display shared` | 四个独立亮点 / 一个共享亮点 |
| `!reverse on` / `!reverse off` | 仅翻转 / 恢复选中旋钮的方向 |
| `!edges 2` / `!edges 4` | 仅修改选中旋钮每次移动所需跳变数，默认 4；2 表示 00 和 11 都是卡位。步进只在卡位状态结算 |
| `!color next` / `!color 1`～`!color 8` | 切换选中旋钮的颜色；共享模式下改变共享亮点颜色 |
| `!brightness 20` | 全局亮度 0～40，默认 40/255 |
| `!reset` | 恢复初始位置和颜色、清空计数和拖尾；保留亮度、显示模式、各旋钮方向和跳变数设置 |
| `!move cw` / `!move ccw` | 模拟选中旋钮移动一步；计入 simulated，不算物理编码器测试 |
| `!rgbtest on` / `!rgbtest off` | RMT 版本手动开启全灯红绿蓝测试 / 返回旋钮显示；开机默认关闭 |

例如只翻转 I 旋钮：

    !knob I
    !reverse on

旋转或按下某个实物旋钮，会把它设为当前选中旋钮。所有设置保存在 RAM，断电复位后恢复默认。

## 稳定性和诊断

使用四个独立 Gray 解码器、A/B 双沿中断、带旋钮编号的事件队列，以及四个独立的 25ms 按键防抖器。各旋钮不会共享旋转累计量或按键状态。

开机等待 150ms 后初始化 RGB，直接显示四个独立亮点，再启用编码器中断；每 250ms 重发同一幅灯光以便恢复显示。这不会自动移动亮点或淡出拖尾。`frames` 因重发而增长是正常的；判断停转保持时看位置、颜色和物理旋转计数。亮度仍限制为 40/255，不启动 Wi-Fi 或蓝牙。全灯红绿蓝测试仅通过 `!rgbtest on` 手动开启。

2026-10-14 排查此前全灯不亮：ESP32 USB 应答正常；使用者确认 GPIO47/U2 输入高电平约3.3V，U2 输出和首颗 RGB DI 高电平约4.87～5V、低电平接近0V。独立 RGB 测试固件经现场确认，40颗均可显示红、绿、蓝。此前全灭的具体原因尚未完全确定；此处的重复发送策略属于稳定性改进，不能据此宣称已确认故障根因。

固件编译、USB 检查及实物旋钮测试结果记录在 `validation` 目录；实际方向和每格步数需操作每个实物旋钮确认。

## 2026-10-14 验证记录

- `knob_encoder` 编译、上传成功；旋钮解码与显示逻辑的本机测试通过。
- 42 项 USB 检查通过，覆盖四旋钮独立控制、共享显示、参数范围、命令恢复和停止时保持状态。USB 模拟移动不算实物旋钮验证。
- 使用者确认 I、D 实物正常；STEP 已记录到正反转和按下事件，显示表现仍在单亮点模式下复核。
- P 旋转时 A 输入变化，但采样中的 B 输入始终为低，未产生有效整步。需检查 P_B 路径，尚不能确认是焊接、元件还是 GPIO 故障。
- 原主机 PCB 中 P_B 连接 SW1 的 B 焊盘、R9 的 1 焊盘、C5 的 1 焊盘和 ESP32 GPIO5；R9 的 2 焊盘接 3V3，C5 的 2 焊盘接 GND。可在 R9/C5 测量，不必探测模组底部焊盘。

首轮上传后的 USB 读取曾出现一段不完整的 panic 文本，来源尚未确认；后续连续查询和实物输入监听未捕获到新的 panic。原始记录保存在 `validation`。

随后使用者断电处理硬件，USB 显示测试因此中断。重新连接后烧入同一份 `rgb_diagnostic` 全灯固件，ESP32 USB 应答正常，但使用者报告全部 RGB 不亮。该情况为当时记录，后续进展见下文。

## 2026-10-15 验证记录

- 使用者发现一个电阻虚焊，未提供位号；处理后确认 `rgb_all_on` 固件能使 40 颗 RGB 全部白色常亮。这并未单独证明此前每次全灭都只有同一个原因。
- 四旋钮版本改用与上述全白程序相同的 RMT 时序，开机关闭全灯自检，直接显示四个旋钮亮点。
- 旋钮解码、按键防抖、方向与回绕、独立拖尾、停转保持和共享模式的本机测试通过；`knob_encoder_rmt` 编译、上传成功。
- 使用者现场确认四旋钮拖影测试通过：正反转跟随、停转保持、按下切色，并确认可看到 STEP 红、P 绿、I 蓝、D 紫四个亮点。验证依据为现场反馈；此前 USB 监听因电脑未识别到设备而结束，没有采集到本次实物旋转计数。原始测试及烧录记录保存在 `validation`。
